# Loop latency calibration

## Goal

Recordings of the pedal return started late because of the delay through the audio interface, mixer and pedal. I wanted the training tool to measure this delay once per run and remove it, so each recorded output lines up sample for sample with its input.

The signal path always goes through the pedal. As the pedal is analogue it adds no real delay, so what is measured is the interface and mixer.

## Approach

- A short log sine sweep (100 Hz to 8 kHz, 0.25 s) is played and recorded on the open duplex stream. I used a sweep rather than a steady sine because a steady sine correlates equally well one period either side of the true delay.
- The delay is found with FFT cross correlation. The magnitude is used so an inverted return still works, and a normalised correlation below 0.3 is treated as "sweep not found" (wrong channel, cable or gain).
- It is measured three times and the median is used. If the three results differ by more than 0.5 ms the calibration fails.
- Calibration runs on the first sample of the first batch, once per sample rate, and is stored on the `TrainingRun`. Later batches and retries reuse it.
- Each capture records extra frames to cover the delay and then removes them from the start of the recording. The tail is back to the fixed 0.25 s rather than 0.25 s plus the reported device latency.
- The manifest records the calibration for each rate, `latency_frames` for each recording and `"latency_compensated": true`. The GUI summary shows the measured latency.
